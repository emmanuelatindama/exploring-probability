# Exploring Probability

Interactive simulations of multiplicative betting games, where the average
outcome and the typical outcome disagree — and the gap between them is the point.

**Live demo:** https://emmanuelatindama.github.io/exploring-probability/

## The headline example

Start with $100. Flip a fair coin: heads multiplies your wealth by 1.5, tails by
0.6. Each round has an expected return of **+5%**, so the game looks like free
money. After 100 rounds:

| | |
|---|---|
| Expected final wealth | **$13,150** |
| Median final wealth | **$0.52** |
| Players ending below $100 | **86.4%** |
| Players ending below $1 | **54.0%** |

Both numbers are correct. The expectation is carried by a handful of
astronomically lucky paths; the median follows the geometric mean
√(1.5 × 0.6) ≈ 0.949, so the typical player decays at −5.3% per round. Averaging
across players and averaging across time give different answers — the process is
non-ergodic.

Then stake only **25%** of your wealth each round instead of everything, and the
same game turns from −5.3%/round to **+0.62%/round**. That optimum is the Kelly
criterion, and the second scenario shows where it comes from.

## Scenarios

- **Ergodic coin flip** — the paradox above
- **Kelly bet sizing** — the resolution, with a growth-rate sweep over bet size
- **Gambler's ruin** — additive bets against two absorbing barriers
- **St Petersburg paradox** — a wager with infinite expected value nobody will pay $20 for
- **Iterated prisoner's dilemma** — a round-robin tournament, then let the winners breed
- **Monty Hall** — the host's knowledge as a dial, not an assumption
- **Shannon's demon** — harvesting a growth rate out of a stock that goes nowhere
- **Insurance and risk pooling** — a contract with negative expected value that both sides are right to sign
- *Parrondo's paradox*, *base rates*, *the birthday problem*, *the secretary problem*, *the two-envelope paradox*, *optional stopping* — declared, not yet built

## Running it locally

It is a static page with no build step. Either open `index.html` directly, or:

```bash
python -m http.server 8000     # then visit http://localhost:8000
```

Plotly loads from a pinned CDN; everything else is local. Scripts are classic
(not ES modules) specifically so `file://` works.

## The Python lab

`lab/` holds the source of truth for the mathematics. The browser engine mirrors
it, and `tests.html` proves the two agree.

```bash
conda activate web-dev

python lab/analytics.py      # print the summary table for both scenarios
python lab/verify.py         # check closed forms vs Monte Carlo; rewrite js/golden.js
python lab/validate_palette.py "#2a78d6,#eb6834,#1baf7a" --mode light --pairs all
```

Then open `tests.html` to verify the JavaScript engine against the golden values
— including that the seeded PRNG matches Python bit for bit.

Requires only numpy and scipy. There is no `node` in this project by design.

## Layout

```
index.html            the whole app
tests.html            engine tests against the Python golden values
js/engine.js          simulation + closed-form analytics
js/scenarios.js       scenario registry — add a scenario here
js/charts.js          Plotly wrappers, colour from CSS custom properties
js/app.js             page wiring
js/golden.js          GENERATED by lab/verify.py
lab/analytics.py      source of truth for the mathematics
lab/verify.py         verification + golden-value generator
lab/validate_palette.py   Python port of the dataviz palette validator
```

## Deploying to GitHub Pages

This is a **project site**, which is why it does not need to be named
`<username>.github.io`. You get exactly one user site per account but unlimited
project sites, each served at `https://<username>.github.io/<repo>/`.

```bash
git init -b main
git add .
git commit -m "Exploring Probability: ergodic coin flip and Kelly sizing"
git remote add origin git@github.com:emmanuelatindama/exploring-probability.git
git push -u origin main
```

Then in the repo: **Settings → Pages → Source: Deploy from a branch →
`main` / `/ (root)`**. First build takes a minute or two.

`.nojekyll` is committed deliberately. It tells Pages to serve the files as-is
rather than running them through Jekyll, whose Liquid template engine would try
to interpret `{{ }}` and `{% %}` inside the JavaScript.

### Linking it from the al-folio site

Add an entry under `_projects/` in the `emmanuelatindama.github.io` repo pointing
at the demo URL. Keeping this in its own repo means a change here never triggers
a rebuild of the academic site, and its JS can never break that site's Liquid
parsing.
